## PhoenixCameraReader.V48.Managed.dll — useful source reference

- SHA-256: `8b250ac01baff51f31c52e7e7c1e987446d5975ff088ab0d7e6d7590a01afc21`.
- PE32+/x64 CLR assembly; 61 types, 226 methods, no P/Invoke maps in metadata.
- Assembly name PhoenixCameraReader.V48.Managed, assembly version 0.0.0.0. The
  filename/assembly name does not establish source lineage or publisher trust.
- Declares Reader.ReadPlayerCameraPose, ReadPlayerCameraAttempt, CameraSchema and
  ComposeCameraQuaternion. Selected IL contains a Player.MainCameraTransform field
  path and transform hierarchy/recheck logic. It still needs caller-supplied read
  transport and matching runtime context; the file alone supplies no live binding.
- **Ten field-reference constants match the pinned current game ELF/metadata**:
  Player.MainCameraTransform, declared UnityEngine.Transform, source offset
  `0x3e8`, its registration RVA, descriptor, field token, metadata/name locations
  and exact field record. See reference-crosscheck.json.

This is useful evidence for a future source-level camera reader review. Correct
field identity does not prove its live value, lifetime, rendered active-camera
selection or shot convention. The assembly defines its own HeadBridge.Mapping
types; it is not a drop-in native V52 plugin and must not be mixed into the current
runtime merely because class names match. No recovered path was enabled live.

## Reproduce and validation

```text
python -m pip install -r requirements.txt
python Inspect-References.py --managed PhoenixCameraReader.V48.Managed.dll --native PhoenixV5.dll --report report.json
python Crosscheck-CameraReference.py libil2cpp.so global-metadata.dat report.json field-check.json
```

The crosscheck reuses the sibling pinned Recover-GameLayout.py parser and exact
current ELF/metadata hashes. The static inspection regenerated byte-identically.
Independent DOS/PE header decoding agreed for both files. Four selected IL bodies
were parsed as bytes. Ten constants matched; altering the reference offset caused
rejection. These are OFFLINE_VALIDATED checks, not Windows/live validation.
See static-inspection.json, reference-crosscheck.json and validation.json.
